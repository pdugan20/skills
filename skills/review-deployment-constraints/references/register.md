# Requirements register

Use the organization's current register if one exists. Otherwise build a compact
derived inventory in the user's authorized internal documentation location. Keep
the underlying policy/authorization records canonical. Entries can be rows or
short sections; do not create a new database merely to enforce this shape.

Capture the following information without inventing missing values:

| Field | Meaning |
| --- | --- |
| Identifier and requirement | Stable local ID, exact obligation or clearly labeled paraphrase; split independently applicable obligations. |
| Source | Verified URL/document ID, section or real control ID, version/effective date and retrieval date. |
| Authority | Approved requirement, engineering decision, proposal, historical assessment or customer request; attributable approval evidence where available. |
| Applicability | Customer/system, environment, component, data category, connectivity and triggering behavior. Unknown is distinct from not applicable. |
| Responsibility | Application, hosting platform, identity provider, organizational process, or shared; supporting mapping and owner. |
| Exceptions | Approving authority, affected scope, conditions, expiry/review date and evidence; distinguish not found from proven absent. |
| Verification | Required evidence, available evidence and gaps. Label suggested tests as review methods, not new policy requirements. |
| Disposition | Candidate or confirmed for a specific scope; review finding kept separate from requirement approval. |
| Maintenance | Who confirms changes, last confirmation, next source review/trigger if established, and superseded entry links. |

A source's publication date and the date it was fetched are different. A control
can be current while an old implementation assessment is obsolete. Confirmation
must establish applicable scope and authority; repeating a claim does not do so.

Keep uncertain candidates advisory. When confirmation arrives, record the actual
decision and its scope, resolve contradictory text, and reassess affected findings.
Do not erase approval history or silently promote all candidates because one passed.

For a large source corpus, disclose the systems, document versions and sections
covered. A bounded inventory can support a focused feature decision without
claiming to enumerate every organizational or regulatory requirement.
